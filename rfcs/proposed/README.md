# Proposed RFCs

This directory contains RFCs open for evaluation. Entry requires a unique RFC
ID, complete metadata, concrete normative diff, guarantee-ledger impact,
compatibility/migration analysis, alternatives, security and complexity impact,
evidence plan, and source provenance.

Proposed RFCs may change in response to review. Revisions preserve material
objections and explain resolution. Implementations may explore feasibility, but
no proposal changes active doctrine merely by existing or by having code.

Exit conditions:

- **accepted**: decision owners approve the exact proposal and conditions; move
  the file to [`../accepted/`](../accepted/);
- **rejected**: the proposal is declined with rationale; move it to
  [`../rejected/`](../rejected/);
- **withdrawn**: record withdrawal as rejection with author rationale so the ID
  and history remain;
- **replaced while proposed**: finalize the old proposal as superseded/rejected
  and link the new RFC.

Relationship to doctrine status: proposed RFCs do not make a doctrine draft,
active, deprecated, or superseded. Status changes occur through accepted
implementation and manifest updates.
