# Rejected RFCs

This directory preserves proposals that were declined or withdrawn. Entry
requires a final decision record explaining the key reasons, evidence
considered, and conditions that could justify a materially new proposal.
Rejection preserves useful analysis and prevents repeated ungrounded debate.

Rejected RFCs are historical. Their proposed normative text is not active and
must not be cited as a repository requirement. Minor factual annotations and
links may be added; changing the proposal requires a new RFC ID.

Rejected RFCs normally have no exit. If later evidence supports the idea, create
a new proposed RFC that links the rejected one, explains changed premises, and
performs current compatibility, security, complexity, and evidence analysis.

Relationship to doctrine status: rejection makes no doctrine status change.
Existing active doctrine remains authoritative.
